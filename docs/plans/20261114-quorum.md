# quorum Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shared code pad for interviews: rooms by URL, one CRDT-synced
CodeMirror editor per room with named live cursors, served by one Rust binary
that keeps rooms only in memory.

**Architecture:** An axum server speaks the standard y-websocket protocol
(`yrs::sync` messages) at `/ws/<room>`, holding one `yrs::Doc` and a map of
awareness entries per room while anyone is connected, behind hard caps. The
front end is an npm workspace: `@quorum/core` (editor setup, Yjs session,
registries, names) and `@quorum/app` (Vite page), whose build is embedded
into the binary with `rust-embed`.

**Tech Stack:** Rust (edition 2024, axum 0.8, tokio, yrs 0.28, rust-embed 8,
clap 4, tokio-tungstenite for tests), TypeScript 7, Vite 8, vitest 5,
CodeMirror 6, yjs 13, y-websocket 3, y-codemirror.next 0.3, thememirror 2,
`@fontsource/jetbrains-mono`, just, GitHub Actions, cargo-zigbuild.

**Spec:** `docs/specs/20261114-quorum.md`

## Global Constraints

- Nothing is written to disk by the server; a room and its doc are dropped when its last connection closes.
- Names are never written to `localStorage`; identity lives in `sessionStorage` under `quorum:identity:<room>`.
- Theme preference lives in `localStorage` under `quorum:theme`.
- Themes: exactly `coolGlow` (default, dark) and `rosePineDawn` (light) from `thememirror`; no invented themes.
- Highlighting is CodeMirror's own (`@codemirror/lang-*`, `@codemirror/legacy-modes`); no other highlighter.
- No code execution, no accounts, no UI framework, no Monaco.
- Room name regex: `^[a-z0-9][a-z0-9-]{0,39}$`.
- Caps: 1000 connections total, 8 per IP, 200 rooms, 16 per room, 1 MiB per incoming message, 1 MiB encoded doc per room, 4 KiB per awareness state, 30 msg/s burst 60, 100 strikes then disconnect, outbox 512 messages per connection.
- Names: max 32 characters after sanitising; fallback `anonymous`.
- Default listen address `127.0.0.1:20481`; flags `--listen`, `--version`; version from env `QUORUM_VERSION` at build time, else `dev`.
- Release targets: `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `x86_64-apple-darwin`, `aarch64-apple-darwin`; archives named `quorum_<version>_<os>_<arch>.tar.gz`.
- License MIT, `Copyright (c) 2026 Roman Timashev`.
- Commit messages are one line, imperative mood, no body, no trailers.
- Close codes (shared by server and client):

  | Code | Name          | Meaning                                    | Client retries |
  | ---- | ------------- | ------------------------------------------ | -------------- |
  | 4000 | BAD_ROOM      | room name fails the regex                  | no             |
  | 4001 | ROOM_FULL     | 16 people already in the room              | on user click  |
  | 4002 | BUSY          | total, per-IP or room-count cap reached    | on user click  |
  | 4003 | DOC_TOO_LARGE | update would push doc past 1 MiB           | no (reload)    |
  | 4004 | RATE_LIMITED  | more than 100 refused messages             | on user click  |
  | 4005 | TOO_SLOW      | outbox full, reader cannot keep up         | yes (auto)     |
  | 4006 | PROTOCOL      | undecodable message or oversized awareness | no             |

## Review Focus

- A paste that pushes the doc past 1 MiB: the paster sees "document too large", the provider stops reconnecting (no resend loop), others keep the previous text. → Task 3 test `update_past_doc_cap_is_rejected`, Task 9 test `doc too large is fatal`.
- A tab that closes or loses network: its cursor vanishes for others at once, not after a 30 s timeout. → Task 6 test `awareness_removed_on_disconnect`.
- Two people auto-assigned the same name or colour: the later one re-picks a free name (unless they typed it themselves) and a free colour. → Task 9 test `resolveClash`.
- Room URLs typed by hand: `/Kernel-Panic-42`, `/kernel-panic-42/`, `/kernel%20panic` open the normalised room; `/a/b` is 404. → Task 5 test `trailing_slash_serves_index`, Task 7 test `normalizeRoom`.
- A late joiner after someone already picked a language: the joiner does not reset it to the default. → Task 9 test `ensureDefaultLang keeps an existing lang`.

### Task 3: Per-room protocol state

**Files:**
- Create: `src/room.rs`

**Interfaces:**
- Consumes: `limits::{MAX_DOC, MAX_AWARENESS_STATE}`.
- Produces:
  - `pub type ConnId = u64;`
  - `pub struct Room` with `Room::new() -> Room`.
  - `Room::greeting(&self) -> Vec<Vec<u8>>`: encoded `Message::Sync(SyncStep1(state_vector))`, followed by an encoded `Message::Awareness` of all stored entries when there are any.
  - `Room::handle(&mut self, from: ConnId, data: &[u8]) -> Result<Vec<Reply>, RoomError>`.
  - `Room::remove_conn(&mut self, conn: ConnId) -> Option<Vec<u8>>`: encoded awareness message marking every client ID owned by `conn` as removed (`clock + 1`, json `"null"`), or `None` if it owned none.
  - `Room::text(&self, name: &str) -> String` (test helper, `#[cfg(test)]` is fine).
  - `pub enum Reply { ToSender(Vec<u8>), ToOthers(Vec<u8>) }`
  - `pub enum RoomError { DocTooLarge, Protocol }`

Behaviour of `handle` per decoded `yrs::sync::Message` (`Message::decode_v1`; decode failure → `Protocol`):

- `Sync(SyncStep1(sv))` → `ToSender(Sync(SyncStep2(diff against sv)))`.
- `Sync(SyncStep2(u))` or `Sync(Update(u))` → size check, decode with `Update::decode_v1` (fail → `Protocol`), apply, `ToOthers(Sync(Update(u)))`.
- `Awareness(update)` → any entry json longer than `MAX_AWARENESS_STATE` → `Protocol`; record `from` as owner of each client ID; keep entries with newer clocks; json `"null"` removes the entry; `ToOthers(original bytes)`.
- `AwarenessQuery` → `ToSender(Awareness(all entries))` if there are any.
- `Auth`, `Custom` → ignored, empty replies.

Doc size check (exact encode is expensive, so keep an estimate): `approx_size` starts at 0 and grows by each accepted update's byte length; when `approx_size + len > MAX_DOC`, recompute `approx_size` as the exact `encode_state_as_update_v1(&StateVector::default()).len()`; reject with `DocTooLarge` if still `approx_size + len > MAX_DOC`. Rejection happens before applying.

Awareness storage: `HashMap<ClientID, (u32 clock, Arc<str> json)>` plus `HashMap<ConnId, HashSet<ClientID>>` owners. Do not use `yrs::sync::Awareness` on the server (it owns observers and is not needed to relay).

### Task 4: Hub admission and fan-out

**Files:**
- Create: `src/hub.rs`

**Interfaces:**
- Consumes: `Room`, `Reply`, `RoomError`, `ConnId`, all caps, `valid_room`.
- Produces:
  - `pub struct Hub`; `Hub::new() -> Arc<Hub>`.
  - `Hub::join(self: &Arc<Self>, room: &str, ip: IpAddr, outbox: mpsc::Sender<Out>) -> Result<Peer, Refusal>`: checks in order bad room, total conns, per-IP, room count (only if the room is new), room size; on success registers the outbox and sends the room's `greeting()` into it.
  - `Hub::leave(&self, peer: &Peer)`: removes the outbox, broadcasts `Room::remove_conn` to the rest, decrements counters, drops the room when empty.
  - `Hub::room_count(&self) -> usize`, `Hub::conn_count(&self) -> usize`.
  - `pub struct Peer { pub id: ConnId, pub room: String, pub ip: IpAddr, slot: Arc<Slot> }`; `Peer::handle(&self, data: &[u8]) -> Result<(), RoomError>`: runs `Room::handle` under the slot lock and delivers replies.
  - `pub enum Out { Data(Vec<u8>), Close(u16) }`; delivery uses `try_send`. When an outbox is full, its sender is removed from the slot; once the hub holds no sender for it, the writer task sees the channel close and closes the socket with `TOO_SLOW`.
  - `pub enum Refusal { BadRoom, RoomFull, Busy }`; `Refusal::close_code(&self) -> u16`.
- Locking: `Hub` holds `std::sync::Mutex<HubState>` (conns, per-IP counts, `HashMap<String, Arc<Slot>>`, next id). `Slot` holds `std::sync::Mutex<SlotInner { room: Room, peers: HashMap<ConnId, mpsc::Sender<Out>> }>`. Order is always hub lock → slot lock; `Peer::handle` takes only the slot lock. No `.await` while holding either.
